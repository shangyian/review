Latency Ladder

For system design, the order matters more than the exact numbers. Each layer below is slower than the one above it, and each one is where a different kind of request ends up. Think of the common path through your system and ask which layer it touches.

  1. chip
  2. RAM
  3. SSD
  4. datacenter
  5. HDD
  6. ocean

1On the chip ~1 ns

if 1 ns = 1 sec: about 1 second

What it is

The L1, L2 and L3 caches, built into the processor itself. L1 is tiny and private to a core, L2 is a bit larger, and L3 is shared by all cores. Each level is bigger and a few times slower than the one before.

Nothing here is persistent, and you don't address it directly. The CPU decides what to keep.

You land here when

  • A hot loop works over a small, contiguous array.
  • Data was just used, so it is still cached.
  • Several threads fight over one lock or one cache line. Even that costs tens of nanoseconds.
about 100× slower

2RAM ~100 ns

if 1 ns = 1 sec: about 2 minutes

How it differs

Memory chips on the other side of a bus, not on the processor. You get gigabytes to terabytes instead of megabytes, at the cost of a trip off the chip every time the cache misses.

Still not persistent. A restart empties it.

You land here when

  • Your working set is bigger than the CPU caches, such as a large in-process hash map.
  • You chase pointers through a big structure, and every hop is a cache miss.
  • A service keeps its data in memory, as a cache or an in-memory database.
about 1,000× slower

3SSD (flash) ~100 µs

if 1 ns = 1 sec: about 1 day

How it differs

The first layer that survives a power cut. A read costs about a thousand times what RAM does, but you get terabytes at a fraction of the price per byte.

This figure is for a small random read. Real drives range from roughly 16 to 150 µs.

You land here when

  • A database needs a page that isn't in its memory buffer.
  • A cache is cold after a restart.
  • A write must be durable before you acknowledge it, so the log is flushed to disk.
about 5× slower

4Same datacenter ~0.5 ms

if 1 ns = 1 sec: about 6 days

How it differs

Reaching another machine costs more than reading a local SSD. The request crosses the network card, switches and the operating system on both ends, and the other machine has to do its work before replying.

That is why moving data off the local box has to buy you something, such as sharing, scale or fault tolerance.

You land here when

  • One service calls another.
  • You read from a remote cache or database.
  • A replicated write waits for a majority of replicas. A consensus commit costs about one round trip plus the followers' disk flush.
about 20× slower

5Spinning disk (HDD) ~10 ms

if 1 ns = 1 sec: about 4 months

How it differs

A mechanical arm has to move and a platter has to spin to the right spot. Random access is painfully slow, but once the head is in place, sequential reads are fast and the storage is cheap.

The cost is in the seek, so one big read beats many small ones.

You land here when

  • Scanning large files in bulk, such as analytics data or backups.
  • Reading archives or cold data nobody has touched in a while.
  • A database does many random reads that miss every faster layer.
about 15× slower

6Across the ocean ~150 ms

if 1 ns = 1 sec: about 5 years

How it differs

Light in fibre covers about 200 km per millisecond, so California to the Netherlands and back can never be much below about 90 ms, and real paths take longer. Faster hardware doesn't help. The only fix is not to make the trip.

Every extra round trip multiplies it. A new connection with a secure handshake needs several before any data moves.

You land here when

  • Users in one region hit a backend in another.
  • A write must be confirmed by a replica on another continent.
  • A chatty protocol makes many sequential requests across regions.

Reading the numbers: these are for a small access or message. Moving a megabyte or more is limited by bandwidth, so the order can shift. Reading 1 MB from an SSD takes about 1 ms, and sending it over a 1 Gbps link takes about 8 ms. Treat every figure as an order of magnitude.
